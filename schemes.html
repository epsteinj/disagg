Disaggregation schemes, step by step

Each axis splits the model across separate chip pools. Below: what happens at each step, what crosses between the pools, and how often. Use Play or step through with Prev / Next.

1 · Prefill / Decode phase split

The two inference phases have opposite hardware appetites — prefill is compute-bound, decode is memory-bandwidth-bound — so run them on pools sized (and chosen) for each.

Prefill pool suits

Compute-dense silicon — high FP8/FP4 peak FLOPS and the best FLOPS-per-dollar. Big HBM and bandwidth matter little; prefill is one parallel pass that reads weights once.

NVIDIA B200 / Rubin · AMD MI355X · Google TPU v7 · Tensordyne
Decode pool suits

Bandwidth- & capacity-dense — re-reads all weights every token, so it wants high HBM bandwidth plus capacity for weights + growing KV. Best bandwidth-per-dollar wins; the phase where inference-specialized / non-NVIDIA parts are most competitive.

B200 / MI355X (8 TB/s) · Groq · Cerebras · d-Matrix · Positron

2 · Attention / FFN — AFD MoE · component split

AFD (Attention-FFN Disaggregation) splits each layer's attention (KV-bound, wants bandwidth) from its FFN / expert bank (capacity + compute-bound). Distinct from wide-EP (scheme 3): AFD splits the component (attention vs FFN onto different pools); wide-EP scales the expert operator itself across many devices. They're composable — MegaScale-Infer / Step-3 do AFD; DeepSeek / Kimi / CloudMatrix do wide-EP.

Attention pool suits

Bandwidth-dense with KV capacity — attention is gated by reading the KV cache, which grows with context × batch. Wants high HBM bandwidth and enough capacity for long contexts.

B200 / MI355X (288 GB) · Groq · d-Matrix (KV in LPDDR tier)
Expert pool suits

Capacity-dense but sparsely read — must hold the entire expert bank (100s of GB for frontier MoE), yet only top-K fire per token, so bandwidth demand is sparse. → cheap, high-capacity memory (LPDDR/CXL-backed) is a strong, cost-efficient fit, not just expensive HBM.

Positron Asimov (2 TB) · d-Matrix (256 GB LPDDR) · Meta MTIA · MI355X (288 GB)

3 · Wide expert parallelism MoE · operator scaling

Spread the expert operator across many devices (EP degree), with attention data-parallel on the same devices. Wider EP → fewer experts per device → less weight read each (faster, cheaper per device) — but more all-to-all, and past the fabric domain it falls onto slow scale-out.

What wins

The expert pool is HBM-bandwidth-bound (only top-K experts read), so the win is spreading wide — ideally one expert per die — so each expert gets a full device's bandwidth.

B200 / GB200 NVL72 · Huawei CloudMatrix (EP320, 1 expert/die)
What gates it

The all-to-all rides the scale-up fabric; spreading past one domain forces it onto scale-out and the comm cost explodes. So a large, fast fabric domain is the enabler.

NVLink NVL72 (72) · Huawei Unified Bus (384) · TPU ICI (256)

4 · Encode / Prefill / Decode multimodal · encoder split

For vision/audio models, split the modality encoder (compute-bound, saturates tensor cores, low HBM demand) from the LLM (prefill + decode). The encoder runs on its own right-sized pool; image embeddings cross to the LLM once per request.

Encoder pool suits

Compute-dense (ViT saturates tensor cores, modest HBM) — and the encoder can run on cheaper / older GPUs since it's not memory-bound.

B200 / H100 · older-gen GPUs · any high-FLOPS part
LLM pool suits

Same as prefill/decode — bandwidth + capacity for the (now image-token-lengthened) prompt and KV.

B200 / MI355X · Groq · d-Matrix

5 · Speculative decoding draft / target split

A small draft model proposes K tokens; the big target verifies them all in one pass — amortizing the target's expensive weight read over many tokens.

Draft pool suits

Tiny-model latency kings — the draft runs autoregressively, so per-token latency dominates and the model is small (≤ a few B). Capacity is trivial; cost should be low.

Groq (lowest latency) · d-Matrix Corsair (1B = 1 card, its lane) · Tenstorrent · edge / small GPUs
Target pool suits

Big compute + bandwidth — verifying K tokens in one pass is more compute-heavy than single-token decode, so it rewards FLOPS on top of the usual decode bandwidth and capacity.

NVIDIA B200 / Rubin · AMD MI355X · big-HBM accelerators

Scale-up = a vendor's intra-rack fabric (NVLink/NVL72, Infinity Fabric, ICI, NeuronLink, Credo, Juniper…) — high bandwidth, limited domain size, single-vendor. Scale-out = cross-rack InfiniBand / Ethernet — lower bandwidth, unbounded, vendor-agnostic. Mixed-vendor pools can only talk scale-out, which is why heterogeneous disaggregation pays a transfer penalty homogeneous deployments avoid.

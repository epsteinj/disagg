Disaggregation schemes, step by step

Each axis splits the model across separate chip pools. Below: what happens at each step, what crosses between the pools, and how often. Use Play or step through with Prev / Next.

1 · Prefill / Decode phase split

The two inference phases have opposite hardware appetites — prefill is compute-bound, decode is memory-bandwidth-bound — so run them on pools sized (and chosen) for each.

2 · Attention / Expert MoE only · component split

For mixture-of-experts models, split each layer's attention (KV-bound, wants bandwidth) from its expert FFN (capacity + compute-bound, holds the whole expert bank).

3 · Speculative decoding draft / target split

A small draft model proposes K tokens; the big target verifies them all in one pass — amortizing the target's expensive weight read over many tokens.

Scale-up = a vendor's intra-rack fabric (NVLink/NVL72, Infinity Fabric, ICI, NeuronLink, Credo, Juniper…) — high bandwidth, limited domain size, single-vendor. Scale-out = cross-rack InfiniBand / Ethernet — lower bandwidth, unbounded, vendor-agnostic. Mixed-vendor pools can only talk scale-out, which is why heterogeneous disaggregation pays a transfer penalty homogeneous deployments avoid.
